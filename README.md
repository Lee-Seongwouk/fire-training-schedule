# 소방훈련 일정

공통 QR코드로 훈련 일정을 신청하고, 한 명의 담당자가 확인·승인하는 웹서비스입니다.

## 사용 순서

1. `/admin`에서 지정한 ChatGPT 계정으로 로그인합니다.
2. 달력에서 날짜를 선택하고 훈련 시작 시간을 등록합니다.
3. `QR코드 공유`에서 이미지를 저장해 문자에 첨부합니다.
4. 소방안전관리자는 로그인 없이 대상물명·이름·전화번호를 입력해 신청합니다.
5. `신청 관리`에서 승인한 뒤 `문자 복사`로 안내 문구를 복사해 직접 발송합니다.

신청 즉시 시간이 잠깁니다. 승인 대기와 확정 신청은 동일한 대상물의 같은 달 중복 신청을 막습니다. 반려·취소하면 시간과 월별 신청 제한이 해제됩니다. 대상물명은 공백·구두점·대소문자 차이를 정규화해 비교하므로 정식 명칭을 사용해야 합니다.

하루 최대 3개의 훈련 시간, 시작 시간 간격 최소 40분(훈련 30분 + 이동 10분)을 서버에서 검증합니다. 일정 변경은 기존 시간을 해제하고 새 시간을 잠그는 단일 데이터베이스 연산으로 처리합니다.

## 개발

Node.js 22.13 이상을 사용합니다. `npm ci`, `npm run db:generate`, `npm run build`를 실행하고 README에 포함된 starter 방식대로 생성된 SQL을 로컬 D1에 적용한 뒤 `npm run dev`로 시작합니다. 원본 SQL은 `drizzle/`에 있습니다.

로컬 `.dev.vars`에는 `ADMIN_EMAIL=seedy@sites.test`를 설정합니다. 미리보기의 로그인은 로컬 테스트 계정이며 실제 사이트의 로그인에 포함되지 않습니다. 게시 환경의 `ADMIN_EMAIL`은 Sites 환경 변수에 별도로 저장합니다. 관리자 권한은 서버에서 매 요청마다 확인합니다. 공개 일정 API는 연락처나 대상물 정보를 반환하지 않습니다.

실제 신청 정보는 D1에 저장합니다. 브라우저 저장소는 예약 상태의 근거로 사용하지 않습니다. 테스트 데이터는 로컬 데이터베이스에만 생성하며, 게시 시 업로드하지 않습니다.

## 검증

`node scripts/verify-schedule.mjs`는 실행 중인 로컬 서버(127.0.0.1:5173)에 대해 권한 검사, 동시 신청, 중복 제한, 시간 간격, 승인·반려·변경·취소 등 26개 검증을 수행합니다. 실제 게시 사이트를 대상으로 실행하지 마세요.

## GitHub Pages 배포

- 신청 화면: https://lee-seongwouk.github.io/fire-training-schedule/
- 관리자 화면 및 예약 API: https://fire-training-schedule.livefuuly.chatgpt.site/admin

GitHub Pages는 정적 화면을 호스팅합니다. 실제 예약은 기존 Sites 서버와 D1에 저장하고, 관리자 로그인은 ChatGPT 계정을 사용합니다. 신청 화면은 `github-pages/main.tsx`에서 공통 React 화면을 사용하며, `lib/deployment.ts`에 연결 주소가 있습니다.

`npm ci` 후 `npm run build:pages`로 `docs/`를 생성합니다. 생성된 `docs/`와 변경한 소스를 커밋하고 `main`에 푸시하면 GitHub Pages가 배포합니다. 저장소 Settings → Pages의 소스는 `main` 브랜치의 `/docs`입니다. `.nojekyll`은 Vite 출력 파일을 그대로 게시하도록 유지합니다.

서버 코드를 변경하면 기존 Sites 서버도 별도로 다시 배포해야 합니다. GitHub Pages 주소에서 공개 일정 조회와 신청만 교차 출처로 허용합니다. 관리자 API는 관리자 인증과 같은 출처 검사를 계속 적용합니다. 개인정보와 인증 비밀은 저장소와 정적 배포 파일에 포함하지 않습니다.
